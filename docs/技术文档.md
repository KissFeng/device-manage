## 1. 项目整体介绍

### 1.1 这个项目是做什么的？

**简单来说**：这是一个设备借用管理系统，就像图书馆借书系统一样，但我们管理的是摄影设备。

**使用场景**：
- 学生想借用学校的相机拍摄作品 → 在系统里提交申请
- 管理员收到申请 → 在系统里批准或拒绝
- 学生使用完毕归还设备 → 管理员在系统里确认归还

### 1.2 为什么要做这个项目？

**传统方式的问题**：
```
学生 → 填写纸质表格 → 管理员手工登记 → 设备借出
     ↓
容易出错、查询不便、状态不明
```

**我们的解决方案**：
```
学生 → 网页提交申请 → 管理员在线审批 → 系统自动记录
     ↓
高效、准确、可追溯
```

### 1.3 项目的核心功能

#### 用户端（学生使用）
1. **登录系统** - 输入用户名和密码
2. **浏览设备** - 看到所有可借的设备（相机、镜头、灯光等）
3. **申请借用** - 选择设备，填写借用目的和归还日期
4. **查看记录** - 看到自己的借用历史

#### 管理端（老师/管理员使用）
1. **仪表盘** - 看到设备总数、用户总数、待审批数量
2. **设备管理** - 添加、修改、删除设备
3. **用户管理** - 添加、修改、删除用户
4. **借用审批** - 批准或拒绝学生的借用申请
5. **归还确认** - 学生归还后，管理员确认

### 2.2 前端和后端是如何配合的？

**前后端分离架构**：

```
┌─────────────┐                    ┌─────────────┐
│   前端       │  ←── HTTP请求 ──→  │    后端      │
│  (浏览器)    │      (JSON)        │  (服务器)    │
│             │                    │             │
│  HTML页面    │                    │  处理业务    │
│  显示数据    │                    │  操作数据库   │
└─────────────┘                    └─────────────┘
```

**举个例子**：

1. 用户在浏览器打开设备列表页面（前端）
2. 页面加载后，JavaScript发送请求到后端：`GET /devices`
3. 后端收到请求，从数据库查询设备数据
4. 后端返回JSON格式的数据给前端
5. 前端JavaScript接收数据，动态生成HTML显示在页面上

**为什么要分离**？
- 前端专注界面展示，后端专注业务逻辑
- 可以独立开发、独立部署
- 前端可以换成手机App，后端不用改

#### 技术2：MyBatis Plus（数据库操作）

**是什么**？
- MyBatis Plus是一个数据库操作工具
- 帮我们把Java对象和数据库表对应起来

**传统方式 vs MyBatis Plus**：

**传统JDBC方式**（复杂）：
```java
// 需要写很多代码
Connection conn = DriverManager.getConnection(url, user, password);
String sql = "SELECT * FROM users WHERE id = ?";
PreparedStatement stmt = conn.prepareStatement(sql);
stmt.setLong(1, userId);
ResultSet rs = stmt.executeQuery();
if (rs.next()) {
    User user = new User();
    user.setId(rs.getLong("id"));
    user.setUsername(rs.getString("username"));
    // ... 还要一个个字段设置
}
// 还要关闭连接、处理异常...
```

**MyBatis Plus方式**（简单）：
```java
// 只需要一行代码！
User user = userMapper.selectById(userId);
```

**怎么实现的**？

**步骤1：定义实体类（Entity）**

```java
@Data  // Lombok注解，自动生成getter/setter
@TableName("users")  // 对应数据库的users表
public class User {
    @TableId(type = IdType.AUTO)  // 主键，自动增长
    private Long id;
    
    private String username;  // 对应数据库的username字段
    private String password;
    private String realName;
    private String role;
    private String status;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

**步骤2：定义Mapper接口**
```java
// 继承BaseMapper，就自动有了增删改查方法
public interface UserMapper extends BaseMapper<User> {
    // 不用写任何代码，就已经有了：
    // - selectById(id)      查询单个
    // - selectList(wrapper) 查询列表
    // - insert(user)        插入
    // - updateById(user)    更新
    // - deleteById(id)      删除
}
```

**步骤3：在Service中使用**
```java
@Service
public class UserServiceImpl implements UserService {
    @Autowired  // 自动注入Mapper
    private UserMapper userMapper;
    
    public User getUserById(Long id) {
        return userMapper.selectById(id);  // 直接调用
    }
}
```

#### 技术3：Spring Security + JWT（安全认证）

**是什么**？
- Spring Security：安全框架，负责认证（你是谁）和授权（你能干什么）
- JWT：一种Token格式，用于在前后端之间传递用户信息

**为什么需要认证**？
- 防止未登录用户访问系统
- 防止普通用户访问管理员功能
- 保护用户数据安全

**JWT的工作原理**（重点理解）：

```
┌──────────────────────────────────────────────────────┐
│  第1步：用户登录                                      │
├──────────────────────────────────────────────────────┤
│  用户输入：username=admin, password=123456           │
│  后端验证：查数据库，密码正确 ✓                      │
│  后端生成Token：eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...│
│  Token内容：{userId: 1, username: "admin", role: "ADMIN"}│
│  返回给前端：{token: "...", userInfo: {...}}         │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│  第2步：前端保存Token                                 │
├──────────────────────────────────────────────────────┤
│  localStorage.setItem('token', token);               │
│  // Token保存在浏览器本地存储中                       │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│  第3步：后续请求携带Token                             │
├──────────────────────────────────────────────────────┤
│  前端发送请求：GET /devices                           │
│  请求头：Authorization: Bearer eyJhbGci...           │
│  // 每次请求都带上Token                              │
└──────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────┐
│  第4步：后端验证Token                                 │
├──────────────────────────────────────────────────────┤
│  后端接收请求 → 提取Token → 验证签名 → 解析内容      │
│  如果Token有效：继续处理请求                          │
│  如果Token无效：返回401错误，要求重新登录             │
└──────────────────────────────────────────────────────┘
```

**代码实现**：

```java
// 1. 生成Token（登录时）
public String generateToken(Long userId, String username, String role) {
    Map<String, Object> claims = new HashMap<>();
    claims.put("userId", userId);      // 放入用户ID
    claims.put("username", username);  // 放入用户名
    claims.put("role", role);          // 放入角色
    
    Date now = new Date();
    Date expiryDate = new Date(now.getTime() + 86400000);  // 24小时后过期
    
    return Jwts.builder()
            .claims(claims)           // 设置内容
            .issuedAt(now)           // 签发时间
            .expiration(expiryDate)  // 过期时间
            .signWith(key)           // 用密钥签名
            .compact();              // 生成Token字符串
}

// 2. 验证Token（每次请求时）
public Boolean validateToken(String token) {
    try {
        Claims claims = getClaimsFromToken(token);  // 解析Token
        return !claims.getExpiration().before(new Date());  // 检查是否过期
    } catch (Exception e) {
        return false;  // Token无效
    }
}
```

**密码加密**：

```java
// 为什么要加密？
// 如果数据库被黑客攻击，密码明文存储会导致所有用户账号泄露

// 注册/创建用户时：加密密码
String rawPassword = "123456";  // 用户输入的原始密码
String encodedPassword = passwordEncoder.encode(rawPassword);
// 加密后：$2a$10$b68xPCyu2uuxoo9tVV/XM.HB4vd5EksRJl2E8rTY8g.i7o3TnD3XW
user.setPassword(encodedPassword);  // 存储加密后的密码

// 登录时：验证密码
boolean isMatch = passwordEncoder.matches(rawPassword, encodedPassword);
if (isMatch) {
    // 密码正确，允许登录
} else {
    // 密码错误，拒绝登录
}
```

**BCrypt的特点**：
- 单向加密，无法解密（只能验证是否匹配）
- 每次加密结果不同（但都能验证通过）
- 即使数据库泄露，黑客也无法得到原始密码

### 3.2 后端代码结构（分层架构）

我们的后端代码分为几层，每层负责不同的事情：

```
┌─────────────────────────────────────────────────────┐
│  Controller层（控制器）                              │
│  作用：接收前端请求，调用Service，返回响应           │
│  文件位置：controller/                               │
├─────────────────────────────────────────────────────┤
│  Service层（业务逻辑）                               │
│  作用：处理业务逻辑，比如验证、计算、调用Mapper      │
│  文件位置：service/ 和 service/impl/                 │
├─────────────────────────────────────────────────────┤
│  Mapper层（数据访问）                                │
│  作用：操作数据库，执行SQL语句                       │
│  文件位置：mapper/ 和 resources/mapper/              │
├─────────────────────────────────────────────────────┤
│  Entity层（实体类）                                  │
│  作用：对应数据库表，一个类对应一张表                │
│  文件位置：entity/                                   │
├─────────────────────────────────────────────────────┤
│  DTO/VO层（数据传输对象）                            │
│  作用：前后端交互的数据格式                          │
│  文件位置：dto/ 和 vo/                               │
└─────────────────────────────────────────────────────┘
```

#### 举个例子：查询用户列表的完整流程

**第1步：前端发送请求**
```javascript
// 前端JavaScript代码
fetch('http://localhost:9011/admin/users?page=1&size=10', {
    method: 'GET',
    headers: {
        'Authorization': 'Bearer ' + token  // 携带Token
    }
})
```

**第2步：Controller接收请求**
```java
// 文件：AdminUserController.java
@RestController  // 表示这是一个控制器，处理HTTP请求
@RequestMapping("/admin/users")  // 这个类处理 /admin/users 开头的请求
public class AdminUserController {
    
    @Autowired  // 自动注入UserService
    private UserService userService;
    
    // 处理 GET /admin/users 请求
    @GetMapping
    public Result<PageResult<User>> getUserList(
            @RequestParam(required = false) String username,  // 查询参数：用户名
            @RequestParam(required = false) String role,      // 查询参数：角色
            @RequestParam(defaultValue = "1") Integer page,   // 查询参数：页码，默认1
            @RequestParam(defaultValue = "10") Integer size   // 查询参数：每页数量，默认10
    ) {
        // 调用Service层的方法
        PageResult<User> result = userService.getUserList(username, role, page, size);
        
        // 返回统一格式的响应
        return Result.success("获取成功", result);
    }
}
```

**理解要点**：
- `@RestController`：告诉Spring这是一个控制器
- `@RequestMapping`：定义这个类处理哪些URL
- `@GetMapping`：处理GET请求（查询数据）
- `@PostMapping`：处理POST请求（创建数据）
- `@PutMapping`：处理PUT请求（更新数据）
- `@DeleteMapping`：处理DELETE请求（删除数据）
- `@RequestParam`：获取URL中的查询参数，比如 `?page=1&size=10`
- `@PathVariable`：获取URL路径中的变量，比如 `/users/{id}`

**第3步：Service处理业务逻辑**

```java
// 文件：UserServiceImpl.java
@Service  // 表示这是一个服务类
public class UserServiceImpl implements UserService {
    
    @Autowired  // 自动注入Mapper
    private UserMapper userMapper;
    
    @Override
    public PageResult<User> getUserList(String username, String role, 
                                         Integer page, Integer size) {
        // 1. 计算偏移量（分页用）
        Integer offset = (page - 1) * size;
        // 比如：第1页，offset=0；第2页，offset=10
        
        // 2. 调用Mapper查询数据
        List<User> list = userMapper.selectUserList(username, role, offset, size);
        
        // 3. 查询总数
        Long total = userMapper.countUsers(username, role);
        
        // 4. 封装成分页结果
        return new PageResult<>(total, page, size, list);
    }
}
```

**理解要点**：
- Service层负责业务逻辑，比如计算、验证、调用Mapper
- 不直接操作数据库，而是调用Mapper
- 可以调用多个Mapper，组合复杂的业务逻辑

**第4步：Mapper操作数据库**

```java
// 文件：UserMapper.java（接口）
public interface UserMapper extends BaseMapper<User> {
    // 自定义查询方法
    List<User> selectUserList(@Param("username") String username,
                              @Param("role") String role,
                              @Param("offset") Integer offset,
                              @Param("size") Integer size);
    
    Long countUsers(@Param("username") String username,
                    @Param("role") String role);
}
```

```xml
<!-- 文件：UserMapper.xml（SQL语句） -->
<mapper namespace="chat.hbcit.devicemanagebackend.mapper.UserMapper">
    
    <!-- 查询用户列表 -->
    <select id="selectUserList" resultType="chat.hbcit.devicemanagebackend.entity.User">
        SELECT id, username, password, real_name, role, status, created_at, updated_at
        FROM users
        <where>
            <!-- 如果username不为空，添加模糊查询条件 -->
            <if test="username != null and username != ''">
                AND username LIKE CONCAT('%', #{username}, '%')
            </if>
            <!-- 如果role不为空，添加精确查询条件 -->
            <if test="role != null and role != ''">
                AND role = #{role}
            </if>
        </where>
        ORDER BY created_at ASC
        LIMIT #{offset}, #{size}
    </select>
    
    <!-- 统计用户总数 -->
    <select id="countUsers" resultType="java.lang.Long">
        SELECT COUNT(*)
        FROM users
        <where>
            <if test="username != null and username != ''">
                AND username LIKE CONCAT('%', #{username}, '%')
            </if>
            <if test="role != null and role != ''">
                AND role = #{role}
            </if>
        </where>
    </select>
    
</mapper>
```

**理解要点**：
- Mapper接口定义方法名
- XML文件写SQL语句
- `#{username}` 是占位符，会自动替换成参数值
- `<if>` 标签实现动态SQL，根据条件决定是否添加WHERE条件

**第5步：返回结果给前端**

#### 概念1：依赖注入（@Autowired）

**是什么**？
- 不用自己new对象，Spring自动帮你创建并注入

**传统方式**：
```java
public class UserServiceImpl {
    // 需要自己创建Mapper对象
    private UserMapper userMapper = new UserMapperImpl();
}
```

**Spring方式**：
```java
public class UserServiceImpl {
    @Autowired  // Spring自动注入
    private UserMapper userMapper;

}
```

**为什么这样做**？
- 解耦：不需要关心对象如何创建
- 方便测试：可以注入Mock对象
- 统一管理：Spring容器管理所有对象

#### 概念3：统一响应格式（Result）

**为什么需要统一格式**？
- 前端可以用同样的方式处理所有响应
- 便于错误处理
- 代码更规范

**Result类的设计**：
```java
public class Result<T> {
    private Integer code;      // 状态码：200成功，400/401/403/500错误
    private String message;    // 消息：给用户看的提示
    private T data;           // 数据：查询结果、创建的对象等
    
    // 成功响应（带数据）
    public static <T> Result<T> success(T data) {
        return new Result<>(200, "操作成功", data);
    }
    
    // 成功响应（自定义消息）
    public static <T> Result<T> success(String message, T data) {
        return new Result<>(200, message, data);
    }
    
    // 失败响应
    public static <T> Result<T> error(Integer code, String message) {
        return new Result<>(code, message, null);
    }
}
```

**使用示例**：
```java
// 成功的情况
return Result.success("获取成功", userList);
// 返回：{"code": 200, "message": "获取成功", "data": [...]}

// 失败的情况
```

#### 概念4：异常处理

**为什么需要异常处理**？

- 程序运行中可能出现各种错误
- 需要统一处理，返回友好的错误提示

**我们的实现**：

**步骤1：定义业务异常类**
```java
// 文件：BusinessException.java
public class BusinessException extends RuntimeException {
    private Integer code;  // 错误码
    
    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }
    
    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }
}
```

**步骤2：在业务代码中抛出异常**
```java
public User getUserById(Long id) {
    User user = userMapper.selectById(id);
    if (user == null) {
        // 抛出业务异常
        throw new BusinessException(404, "用户不存在");
    }
    return user;
}
```

**步骤3：全局异常处理器统一捕获**
```java
// 文件：GlobalExceptionHandler.java
@RestControllerAdvice  // 全局异常处理器
public class GlobalExceptionHandler {
    
    // 捕获业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<?> handleBusinessException(BusinessException e) {
        // 返回统一格式的错误响应
        return Result.error(e.getCode(), e.getMessage());
    }
    
    // 捕获参数校验异常
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining(", "));
        return Result.error(400, message);
    }
    
    // 捕获所有其他异常
    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        logger.error("系统异常", e);
        return Result.error(500, "系统内部错误");
    }
}
```

**好处**：
- 不需要在每个方法里写try-catch
- 统一的错误响应格式
- 避免敏感信息泄露

1. 学生申请借用"佳能 EOS R5"（设备模板）
2. 系统查询该设备下的所有实例
3. 筛选出状态为"正常"且未被借用的实例
4. 自动分配第一个可用实例（比如001）

```javascript
// 文件：api.js

// 后端API地址
const API_BASE_URL = 'http://localhost:9011';

// 统一请求函数
async function request(url, options = {}) {
    const token = localStorage.getItem('token');  // 从本地存储获取Token
    
    // 设置请求头
    const headers = {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${token}`  // 携带Token
    };
    
    // 发送请求
    const response = await fetch(`${API_BASE_URL}${url}`, {
        ...options,
        headers: headers
    });
    
    // 处理响应
    const data = await response.json();
    return data;
}

// GET请求（查询数据）
async function get(url, params = {}) {
    const queryString = new URLSearchParams(params).toString();
    const finalUrl = queryString ? `${url}?${queryString}` : url;
    return request(finalUrl, { method: 'GET' });
}

// POST请求（创建数据）
async function post(url, data = {}) {
    return request(url, {
        method: 'POST',
        body: JSON.stringify(data)  // 把对象转换成JSON字符串
    });
}
```

```java
@Transactional  // 开启事务
public BorrowRecord applyBorrow(Long userId, BorrowRecord record) {
    // 1. 验证设备是否存在
    Device device = deviceMapper.selectById(record.getDeviceId());
    if (device == null) {
        throw new BusinessException("设备不存在");
    }
    
    // 2. 查找可用的设备实例
    List<DeviceInstance> instances = deviceInstanceMapper
        .selectWithBorrowStatus(record.getDeviceId());
    
    DeviceInstance availableInstance = null;
    for (DeviceInstance instance : instances) {
        // 检查状态是否为正常
        if ("NORMAL".equals(instance.getStatus())) {
            // 检查是否已被借用
            Long borrowCount = borrowRecordMapper.selectCount(
                new LambdaQueryWrapper<BorrowRecord>()
                    .eq(BorrowRecord::getDeviceInstanceId, instance.getId())
                    .in(BorrowRecord::getStatus, "PENDING", "APPROVED")
            );
            
            if (borrowCount == 0) {
                availableInstance = instance;  // 找到可用实例
                break;
            }
        }
    }
    
    if (availableInstance == null) {
        throw new BusinessException("该设备暂无可用实例");
    }
    
    // 3. 创建借用记录
    record.setUserId(userId);
    record.setDeviceInstanceId(availableInstance.getId());
    record.setStatus("PENDING");  // 状态：待审批
    borrowRecordMapper.insert(record);
    
    return record;
}
```

### 5.4 设备状态计算逻辑（重要）

**问题**：一个设备有多个实例，如何显示设备的整体状态？

**解决方案**：根据所有实例的状态，计算设备的整体状态

**计算规则**：
```java
private String calculateDeviceStatus(List<DeviceInstanceVO> instances) {
    if (instances == null || instances.isEmpty()) {
        return "NORMAL";  // 没有实例，默认正常
    }
    
    boolean hasBorrowed = false;     // 是否有实例被借用
    boolean hasMaintenance = false;  // 是否有实例在维修
    boolean allScrapped = true;      // 是否所有实例都报废
    
    // 遍历所有实例
    for (DeviceInstanceVO inst : instances) {
        if (inst.getBorrowed()) {
            hasBorrowed = true;  // 有实例被借用
        }
        if ("MAINTENANCE".equals(inst.getStatus())) {
            hasMaintenance = true;  // 有实例在维修
        }
        if (!"SCRAPPED".equals(inst.getStatus())) {
            allScrapped = false;  // 不是所有实例都报废
        }
    }
    
    // 优先级：已报废 > 借用中 > 维修中 > 正常
    if (allScrapped) {
        return "SCRAPPED";  // 所有实例都报废 → 已报废
    }
    if (hasBorrowed) {
        return "BORROWED";  // 有实例被借用 → 借用中
    }
    if (hasMaintenance) {
        return "MAINTENANCE";  // 有实例在维修 → 维修中
    }
    return "NORMAL";  // 其他情况 → 正常
}
```

**举例说明**：
```
设备：佳能 EOS R5
  ├─ 实例1：正常
  ├─ 实例2：借用中  ← 有实例被借用
  └─ 实例3：正常
→ 设备整体状态：借用中

设备：索尼 A7M4
  ├─ 实例1：正常
  ├─ 实例2：维修中  ← 有实例在维修
  └─ 实例3：正常
→ 设备整体状态：维修中

设备：尼康 Z9
  ├─ 实例1：已报废
  ├─ 实例2：已报废  ← 所有实例都报废
  └─ 实例3：已报废
→ 设备整体状态：已报废
```

## 7. 常见问题解答

### Q1：什么是前后端分离？为什么要分离？

**答**：

**传统方式（不分离）**：
```
用户访问 → 后端生成HTML页面 → 返回完整页面给用户
```
例如：JSP、Thymeleaf等模板引擎

**前后端分离**：
```
用户访问 → 前端HTML页面（静态） → JavaScript请求后端API → 后端返回JSON数据 → 前端渲染
```

**为什么要分离**？
1. **职责清晰**：前端负责展示，后端负责逻辑
2. **独立开发**：前端和后端可以并行开发，互不影响
3. **独立部署**：前端可以部署到CDN，后端可以部署到服务器
4. **易于维护**：修改界面不需要动后端，修改逻辑不需要动前端
5. **可扩展**：后端API可以给网页、手机App、小程序共用

---

### Q2：什么是RESTful API？

**答**：

RESTful是一种API设计风格，核心思想是：
- 用URL表示资源（名词）
- 用HTTP方法表示操作（动词）

**示例**：
```
资源：用户（users）

GET    /users       → 获取所有用户（查询）
GET    /users/1     → 获取ID=1的用户（查询单个）
POST   /users       → 创建新用户（新增）
PUT    /users/1     → 更新ID=1的用户（修改）
DELETE /users/1     → 删除ID=1的用户（删除）
```

**为什么这样设计**？
- 语义清晰：一看URL就知道操作什么资源
- 统一规范：所有资源都用同样的方式操作
- 易于理解：符合HTTP协议的设计理念

---

### Q3：什么是依赖注入（@Autowired）？

**答**：

**传统方式**（自己创建对象）：
```java
public class UserServiceImpl {
    private UserMapper userMapper = new UserMapperImpl();  // 自己new
}
```
问题：
- 代码耦合度高
- 难以测试
- 难以替换实现

**Spring方式**（依赖注入）：
```java
public class UserServiceImpl {
    @Autowired  // Spring自动注入
    private UserMapper userMapper;
}
```
好处：
- 不需要关心对象如何创建
- Spring容器统一管理
- 易于测试和替换

**工作原理**：
1. Spring启动时，扫描所有带 `@Component`、`@Service`、`@Repository` 等注解的类
2. 创建这些类的对象（Bean），放入Spring容器
3. 当遇到 `@Autowired` 时，从容器中找到对应的Bean注入进去

---

### Q4：什么是事务（@Transactional）？

**答**：

**事务**：一组数据库操作，要么全部成功，要么全部失败（回滚）

**为什么需要事务**？

**场景**：批准借用申请
```java
// 没有事务的情况（危险）
public void approveBorrow(Long recordId) {
    // 操作1：更新借用记录状态
    borrowRecordMapper.updateById(record);  // 成功
    
    // 操作2：减少设备库存
    deviceMapper.updateStock(deviceId);  // 失败（比如网络中断）
    
    // 结果：借用记录更新了，但库存没减少 → 数据不一致！
}
```

**有事务的情况（安全）**：
```java
@Transactional  // 开启事务
public void approveBorrow(Long recordId) {
    // 操作1：更新借用记录状态
    borrowRecordMapper.updateById(record);
    
    // 操作2：减少设备库存
    deviceMapper.updateStock(deviceId);  // 如果这里失败
    
    // Spring会自动回滚操作1，保证数据一致性
}
```

**事务的特性（ACID）**：
- **A**tomicity（原子性）：要么全做，要么全不做
- **C**onsistency（一致性）：数据从一个一致状态到另一个一致状态
- **I**solation（隔离性）：多个事务互不干扰
- **D**urability（持久性）：事务提交后，数据永久保存

### Q5：为什么要用Lombok？

**答**：

**Lombok**：一个Java库，通过注解自动生成代码

**不用Lombok**（传统方式）：

```java
public class User {

    private String username;
    private String password;

    public String getUsername() {

    // ... 还有很多getter/setter
    
    // 还要写toString、equals、hashCode等方法
}
```

```java
@Data  // 一个注解搞定！
```

`@Data` 注解会自动生成：

**其他常用注解**：
- `@Getter`：只生成getter
- `@Setter`：只生成setter
- `@NoArgsConstructor`：生成无参构造函数
- `@AllArgsConstructor`：生成全参构造函数

### Q7：为什么要分DTO、VO、Entity？

**答**：

这三种对象虽然看起来很像，但用途不同：

**Entity（实体类）**：
- 对应数据库表
- 包含数据库的所有字段
- 用于MyBatis操作数据库

```java
@TableName("users")
public class User {
    private Long id;
    private String username;
    private String password;  // 包含密码字段
    private String realName;
    private String role;
    private String status;
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}
```

**DTO（Data Transfer Object，数据传输对象）**：
- 用于接收前端传来的数据
- 只包含需要的字段
- 可以添加校验注解

```java
public class LoginRequest {
    @NotBlank(message = "用户名不能为空")
    private String username;
    
    @NotBlank(message = "密码不能为空")
    private String password;
    
    // 不包含其他字段，只要用户名和密码
}
```

**VO（View Object，视图对象）**：
- 用于返回给前端的数据
- 可以组合多个表的数据
- 不包含敏感信息（比如密码）

```java
public class UserInfo {
    private Long id;
    private String username;
    private String realName;
    private String role;
    
    // 不包含password字段，保护隐私
}
```

**为什么要分开**？
1. **安全性**：不把密码等敏感信息返回给前端
2. **灵活性**：前端需要的数据和数据库结构可能不一样
3. **解耦**：数据库表结构改变，不影响API接口

### Q8：什么是MyBatis的动态SQL？

**答**：

动态SQL：根据条件动态生成SQL语句

**场景**：用户搜索功能

- 如果用户输入了用户名，就按用户名搜索
- 如果用户选择了角色，就按角色筛选
- 如果都没输入，就查询所有

**传统方式**（写多个SQL）：
```java
// 需要写很多if-else
if (username != null && role != null) {
    sql = "SELECT * FROM users WHERE username LIKE ? AND role = ?";
} else if (username != null) {
    sql = "SELECT * FROM users WHERE username LIKE ?";
} else if (role != null) {
    sql = "SELECT * FROM users WHERE role = ?";
} else {
    sql = "SELECT * FROM users";
}
```

**MyBatis动态SQL**（一个SQL搞定）：
```xml
<select id="selectUserList" resultType="User">
    SELECT * FROM users
    <where>
        <if test="username != null and username != ''">
            AND username LIKE CONCAT('%', #{username}, '%')
        </if>
        <if test="role != null and role != ''">
            AND role = #{role}
        </if>
    </where>
</select>
```

**执行效果**：
```java
// 情况1：username="admin", role=null
// 生成SQL：SELECT * FROM users WHERE username LIKE '%admin%'

// 情况2：username=null, role="ADMIN"
// 生成SQL：SELECT * FROM users WHERE role = 'ADMIN'

// 情况3：username="admin", role="ADMIN"
// 生成SQL：SELECT * FROM users WHERE username LIKE '%admin%' AND role = 'ADMIN'

// 情况4：username=null, role=null
// 生成SQL：SELECT * FROM users
```

- 不要存储非常敏感的信息

### Q12：常见错误及解决方法

#### 错误1：404 Not Found

**原因**：
- URL写错了
- Controller的@RequestMapping路径不对
- 方法的@GetMapping/@PostMapping等注解缺失

**解决**：
1. 检查前端请求的URL是否正确
2. 检查后端Controller的路径映射
3. 查看后端启动日志，确认接口是否注册成功

---

#### 错误2：401 Unauthorized

**原因**：
- Token无效或过期
- 请求头中没有携带Token
- Token格式错误

**解决**：
1. 检查localStorage中是否有token
2. 检查请求头是否正确：`Authorization: Bearer <Token>`
3. 重新登录获取新Token

---

#### 错误3：403 Forbidden

**原因**：
- 用户没有权限访问该接口
- 比如普通用户访问管理员接口

**解决**：
1. 检查用户的角色
2. 检查接口的权限要求
3. 确认是否用对了账号

---

#### 错误4：500 Internal Server Error

**原因**：
- 后端代码出错
- 数据库连接失败
- 空指针异常等

**解决**：
1. 查看后端控制台的错误日志
2. 检查数据库是否启动
3. 检查配置文件中的数据库连接信息
4. 使用断点调试，定位错误位置

---

#### 错误5：跨域错误（CORS）

**错误信息**：
```
Access to fetch at 'http://localhost:9011/devices' from origin 'http://localhost:9012' 
has been blocked by CORS policy
```

**原因**：
- 浏览器的安全策略，阻止跨域请求
- 前端运行在9012端口，后端运行在9011端口，属于跨域

**解决**：
- 后端已经配置了CORS（SecurityConfig.java）
- 如果还有问题，检查配置是否生效

**后端代码**：
```java
// 文件：AuthServiceImpl.java

@Service
public class AuthServiceImpl implements AuthService {
    
    @Autowired
    private UserMapper userMapper;  // 注入Mapper，用于查询数据库
    
    @Autowired
    private JwtUtil jwtUtil;  // 注入JWT工具类，用于生成Token
    
    @Autowired
    private PasswordEncoder passwordEncoder;  // 注入密码加密器，用于验证密码
    
    @Override
    public LoginResponse login(LoginRequest request) {
        // 步骤1：根据用户名查询数据库
        LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<>();
        queryWrapper.eq(User::getUsername, request.getUsername());
        // 相当于SQL：SELECT * FROM users WHERE username = ?
        
        User user = userMapper.selectOne(queryWrapper);
        
        // 步骤2：检查用户是否存在
        if (user == null) {
            // 用户不存在，抛出异常
            throw new BusinessException(401, "用户名或密码错误");
            // 注意：不要提示"用户不存在"，避免泄露信息
        }
        
        // 步骤3：验证密码
        boolean isMatch = passwordEncoder.matches(
            request.getPassword(),  // 用户输入的原始密码
            user.getPassword()      // 数据库中的加密密码
        );
        
        if (!isMatch) {
            // 密码错误，抛出异常
            throw new BusinessException(401, "用户名或密码错误");
        }
        
        // 步骤4：检查用户状态
        if (!"ACTIVE".equals(user.getStatus())) {
            // 用户被禁用，抛出异常
            throw new BusinessException(403, "用户已被禁用，请联系管理员");
        }
        
        // 步骤5：生成JWT Token
        String token = jwtUtil.generateToken(
            user.getId(),       // 用户ID
            user.getUsername(), // 用户名
            user.getRole()      // 角色
        );
        
        // 步骤6：构建用户信息（不包含密码）
        UserInfo userInfo = new UserInfo();
        userInfo.setId(user.getId());
        userInfo.setUsername(user.getUsername());
        userInfo.setRealName(user.getRealName());
        userInfo.setRole(user.getRole());
        
        // 步骤7：构建响应对象
        LoginResponse response = new LoginResponse();
        response.setToken(token);
        response.setUserInfo(userInfo);
        
        // 步骤8：记录日志
        logger.info("用户登录成功，用户名：{}，角色：{}", user.getUsername(), user.getRole());
        
        // 步骤9：返回响应
        return response;
    }
}
```

### 9.2 完整的设备借用代码（带详细注释）

```java
// 文件：BorrowServiceImpl.java

@Service
public class BorrowServiceImpl implements BorrowService {
    
    @Autowired
    private BorrowRecordMapper borrowRecordMapper;
    
    @Autowired
    private DeviceMapper deviceMapper;
    
    @Autowired
    private DeviceInstanceMapper deviceInstanceMapper;
    
    /**
     * 提交借用申请
     * @param userId 用户ID（从Token中获取）
     * @param record 借用记录（包含deviceId、purpose、expectedReturnDate）
     * @return 创建的借用记录
     */
    @Override
    @Transactional(rollbackFor = Exception.class)  // 开启事务，任何异常都回滚
    public BorrowRecord applyBorrow(Long userId, BorrowRecord record) {
        
        // ========== 步骤1：验证设备是否存在 ==========
        if (record.getDeviceId() == null) {
            throw new BusinessException(400, "设备ID不能为空");
        }
        
        Device device = deviceMapper.selectById(record.getDeviceId());
        if (device == null) {
            throw new BusinessException(404, "设备不存在");
        }
        
        // ========== 步骤2：验证预计归还日期 ==========
        if (record.getExpectedReturnDate() == null || 
            record.getExpectedReturnDate().isBefore(LocalDate.now())) {
            throw new BusinessException(400, "预计归还日期无效");
        }
        
        // ========== 步骤3：查询该设备的所有实例 ==========
        List<DeviceInstance> instances = deviceInstanceMapper
            .selectWithBorrowStatus(record.getDeviceId());
        // 这个方法会查询该设备的所有实例
        
        // ========== 步骤4：筛选可用的实例 ==========
        DeviceInstance availableInstance = null;
        
        for (DeviceInstance instance : instances) {
            // 4.1 检查实例状态是否为正常
            if (!DeviceStatus.NORMAL.getCode().equals(instance.getStatus())) {
                // 如果是维修中或已报废，跳过
                continue;
            }
            
            // 4.2 检查实例是否已被借用
            // 查询该实例是否有状态为PENDING或APPROVED的借用记录
            LambdaQueryWrapper<BorrowRecord> borrowWrapper = new LambdaQueryWrapper<>();
            borrowWrapper.eq(BorrowRecord::getDeviceInstanceId, instance.getId())
                    .in(BorrowRecord::getStatus, 
                        BorrowStatus.PENDING.getCode(),   // 待审批
                        BorrowStatus.APPROVED.getCode()); // 已批准（借用中）
            
            Long borrowCount = borrowRecordMapper.selectCount(borrowWrapper);
            
            if (borrowCount == 0) {
                // 没有借用记录，说明可用
                availableInstance = instance;
                break;  // 找到第一个可用实例就停止
            }
        }
        
        // ========== 步骤5：如果没有可用实例，抛出异常 ==========
        if (availableInstance == null) {
            throw new BusinessException(400, "该设备暂无可用实例");
        }
        
        // ========== 步骤6：创建借用记录 ==========
        record.setDeviceInstanceId(availableInstance.getId());  // 设置实例ID
        record.setQuantity(1);  // 数量固定为1（因为是实例模式）
        record.setUserId(userId);  // 设置借用人ID
        record.setStatus(BorrowStatus.PENDING.getCode());  // 状态：待审批
        
        // 插入数据库
        borrowRecordMapper.insert(record);
        
        // ========== 步骤7：记录日志 ==========
        logger.info("提交借用申请成功，记录ID：{}，用户ID：{}，设备ID：{}，设备实例ID：{}", 
                record.getId(), userId, record.getDeviceId(), record.getDeviceInstanceId());
        
        // ========== 步骤8：返回创建的记录 ==========
        return record;
    }
}
```
