## 1. 项目概述

### 1.1 项目背景

随着媒体行业的快速发展，各类专业设备（相机、镜头、灯光、线材等）的管理和借用需求日益增长。传统的人工管理方式存在以下问题：

- **管理效率低**：设备信息记录在纸质文档中，查询和统计困难
- **库存管理混乱**：无法实时掌握设备可用数量，容易出现超借或设备闲置
- **借用流程不规范**：借用申请、审批、归还流程缺乏统一管理
- **数据统计困难**：无法快速生成设备使用情况统计报表

为了解决这些问题，开发了"光影资产——媒体设备借用管理中心"系统，实现设备管理的数字化、自动化和规范化。

### 1.2 项目目标

本项目旨在构建一个功能完善、操作简便的媒体设备借用管理系统，实现以下目标：

1. **设备信息管理**：实现设备信息的数字化管理，包括设备基本信息、分类管理、状态管理等
2. **借用流程管理**：实现设备借用的全流程管理，包括申请、审批、借用、归还等环节
3. **库存实时管理**：实现设备库存的实时更新，确保库存数据的准确性
4. **权限分级管理**：实现管理员和普通用户的分级权限管理
5. **数据统计分析**：提供设备使用情况的统计和分析功能

### 1.3 项目范围

本项目包括以下功能模块：

- **用户认证与权限管理模块**：用户登录、权限控制、用户信息管理
- **设备管理模块**：设备信息管理、设备分类管理、设备状态管理
- **借用流程管理模块**：设备浏览、借用申请、审批管理、归还确认
- **数据统计模块**：设备使用统计、借用记录查询

### 1.4 用户角色

系统支持两种用户角色：

**超级管理员（Root）**：拥有系统所有权限，可以管理设备、审批借用申请、确认归还、人员管理等

- **管理员（Admin）**：可以管理设备、审批借用申请、确认归还等
- **普通用户（User/Borrower）**：可以浏览设备、提交借用申请、查看自己的借用记录

| update_by | varchar | 64 | NULL | 否 | 更新者 |

## 4. 功能模块详细设计

### 4.1 用户认证与权限模块

#### 4.1.1 用户登录

**功能描述**：用户通过用户名和密码登录系统。

**业务流程**：
1. 用户输入用户名和密码
2. 前端将用户名和密码发送到后端
3. 后端验证用户名和密码
4. 验证成功后，生成JWT Token
5. 返回Token给前端
6. 前端将Token存储到LocalStorage
7. 跳转到系统首页

**技术实现**：
- 使用Spring Security进行密码验证
- 使用BCrypt进行密码加密
- 使用JWT生成Token
- Token有效期为2小时

#### 4.1.2 权限控制

**功能描述**：根据用户角色控制菜单和按钮的显示。

**实现方式**：
- **后端权限控制**：使用`@PreAuthorize`注解在Controller方法上控制接口访问权限
- **前端权限控制**：
  - 路由守卫：检查用户是否有访问该路由的权限
  - 按钮权限：使用`v-hasPermi`指令控制按钮显示

**权限标识规范**：
- 设备管理：`device:info:list`、`device:info:add`、`device:info:edit`、`device:info:remove`
- 分类管理：`device:category:list`、`device:category:add`、`device:category:edit`、`device:category:remove`
- 借用管理：`borrow:record:list`、`borrow:record:approve`、`borrow:record:return`

### 4.2 设备管理模块

#### 4.2.1 设备列表查询

- 设备名称*（必填）

- 可用数量不能大于总数量
- 总数量必须大于0

#### 4.2.3 设备状态管理

**功能描述**：管理员可以变更设备状态（正常、维修中、已报废）。

**业务规则**：
- 设备状态为"维修中"或"已报废"时，该设备不计入可用库存
- 状态变更时，需要更新可用数量
- 如果设备有未归还的借用记录，不能变更为"已报废"

**状态变更逻辑**：
1. 检查设备当前状态
2. 检查是否有未归还的借用记录
3. 更新设备状态
4. 如果变更为"维修中"或"已报废"，从可用数量中扣除
5. 如果从"维修中"或"已报废"变更为"正常"，恢复可用数量

#### 4.2.4 设备分类管理

**功能描述**：管理员可以管理设备分类，包括新增、编辑、删除分类。

**功能点**：
- 分类列表查询（支持分页、搜索）
- 分类新增（分类名称、分类编码、描述等）
- 分类编辑
- 分类删除（检查是否有设备使用该分类）

#### 6.1.3 业务逻辑实现

**设备库存管理逻辑**：

```java
// 审批通过时，减少可用数量
@Transactional
public int approveBorrow(Long recordId, String approveRemark) {
    BorrowRecord record = borrowRecordMapper.selectBorrowRecordById(recordId);
    DeviceInfo device = deviceInfoMapper.selectDeviceInfoById(record.getDeviceId());
    
    // 检查可用数量
    if (device.getAvailableCount() < record.getBorrowCount()) {
        throw new ServiceException("设备可用数量不足");
    }
    
    // 更新借用记录
    record.setStatus("1"); // 已批准
    record.setApproveBy(getUserId());
    record.setApproveTime(new Date());
    record.setApproveRemark(approveRemark);
    borrowRecordMapper.updateBorrowRecord(record);
    
    // 减少设备可用数量
    device.setAvailableCount(device.getAvailableCount() - record.getBorrowCount());
    deviceInfoMapper.updateDeviceInfo(device);
    
    return 1;
}

// 确认归还时，增加可用数量
@Transactional
public int confirmReturn(Long recordId, String returnCheck, String returnRemark) {
    BorrowRecord record = borrowRecordMapper.selectBorrowRecordById(recordId);
    DeviceInfo device = deviceInfoMapper.selectDeviceInfoById(record.getDeviceId());
    
    // 更新借用记录
    record.setStatus("4"); // 已归还
    record.setActualReturnDate(new Date());
    record.setReturnCheck(returnCheck);
    record.setReturnRemark(returnRemark);
    borrowRecordMapper.updateBorrowRecord(record);
    
    // 增加设备可用数量
    device.setAvailableCount(device.getAvailableCount() + record.getBorrowCount());
    deviceInfoMapper.updateDeviceInfo(device);
    
    // 如果设备损坏或丢失，需要处理
    if ("1".equals(returnCheck)) { // 损坏
        // 可以更新设备状态为维修中
    } else if ("2".equals(returnCheck)) { // 丢失
        // 需要减少总数量
        device.setTotalCount(device.getTotalCount() - record.getBorrowCount());
    }
    
    deviceInfoMapper.updateDeviceInfo(device);
    return 1;
}
```
